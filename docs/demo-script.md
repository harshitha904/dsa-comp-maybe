# Lives Group demo — nine acceptance steps

Use synthetic data. Start with `npm run dev`, open http://127.0.0.1:5173 and select Management. Reset demo from the workspace; this restores tickets and retains audit history. The steps below describe expected behavior from the implementation, not a recorded acceptance run.

1. **Show the parallel ticket.** Open T-1042. Explain PO-5521, Bangkok Central Lab, QTS, Thailand and USD 48,000. Quote is already unlocked. Finance and QA/RA have separate sections; completing one must not wait for the other.
2. **Show personal work.** Select Wei Jie and open Needs you. Show Finance tasks, value waiting and age. Open T-1042. Explain that this persona switch demonstrates permissions and is not sign-in. Show that sensitive credit/bank fields are available to Finance, then compare Somchai's filtered view.
3. **Complete Finance's part.** As Wei Jie, review THB 500,000 and 60 days. Explain the synthetic conversion: roughly SGD 19,000 meets the amount threshold, but 60 days fails the 30-day rule, so expert review is required. Complete the credit section with valid fields. Sell on credit unlocks; Thailand delivery stays blocked pending QA/RA.
4. **Complete QA/RA and final check.** Select Dr Nurul, enter a Thailand licence reference and complete the section. Select Priya for MDM's final check. Create the official record only after required expert sections finish. Show the official code, completed state and audit history. Download the simulated SAP payload if desired; no SAP write occurs.
5. **Prevent a duplicate.** Select Somchai, start a Customer request and enter “NUH” or “National University Hospital”. Inspect up to three candidates with activity evidence. Reuse the official record to complete the request, or explicitly choose a new record with a reason. Do not describe this as an automatic merge.
6. **Exercise policies and returns.** Create a different synthetic Customer with SGD 40,000, 30 days and unregulated coverage to demonstrate automatic clearance. Compare with 60-day terms. On a pending expert section, request more information with a reason; the requestor corrects and resubmits it. Show the audit. Approval rules can change new-ticket configuration; existing ticket sections remain fixed. See the gap analysis before demonstrating the business-unit wizard.
7. **Show notification delivery.** Open the bell, follow a task to its ticket, then open “Delivered to your team” / Teams & Outlook preview. Show the adaptive-card actions, digest, quiet hours and delegate settings. State clearly that delivery is simulated. The notification endpoint processes due 24/48/72-hour SLA events when requested; there is no autonomous background job. A nudge is limited to one per section per 24 hours.
8. **Show data and duplicate impact.** Open Insights. Explain 150 canonical customers plus aliases, five markets and three products. Compare recent six-month confirmed demand with the previous six months. Inspect duplicate impact and before/after concentration. Enquiries stay separate from confirmed demand. Consolidation changes the analytical view, not source records.
9. **Backtest and create follow-up work.** Inspect the forecast's six rolling holdouts, baseline and trend scores. Read the actual displayed winner: lower MAE selects it, while MAPE omits zero-actual months. Explain the empirical range's limited evidence. Assign a recommendation, switch to its owner in Needs you and complete the task. Close by naming production gaps: authenticated identity, Microsoft delivery, durable scheduling, validated SAP integration and pilot measurement. No achieved savings are claimed.

The UI is an implemented glass workspace using React and custom CSS. Full Figma frames, a production Microsoft 365 solution and a Python rewrite are not part of this delivered prototype. See [gap analysis](v2-gap-analysis.md) for exact distinctions.
