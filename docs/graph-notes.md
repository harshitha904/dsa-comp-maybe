# Intelligence graph

`Intelligence({ initialCustomerId?: string })` loads `/api/bootstrap` through the shared API helper and preserves `docs/CONTRACT.md`. It derives country → customer relationships and customer → product edges from confirmed orders only. Order edges aggregate quantity and count per customer/product pair; enquiries and setup signals are excluded. Country labels expand SG/MY/TH/ID/VN as well as accepting the full country names in the enriched seed. All counts come from the response.

The initial country is visibly selected as Singapore, with its first customer inspected (the enriched seed starts with National University Hospital). `initialCustomerId` selects the requested record and its country, including when navigation changes it after bootstrap loads, and clears search/product/collision filters. A single-country view keeps country/customer/product lanes. All-country exploration wraps customers across up to three columns at 125px row spacing: 18 customers occupy six rows rather than an 18-row column. Reset filters explicitly opens all countries; users can also choose All countries directly. Pan/zoom/fit controls remain supplied by React Flow.

Orange review outlines and dashed potential-duplicate edges are derived from customer pairs sharing a nonempty identifier or email (trimmed, case insensitive), or an exact normalized name/alias across either record. Name normalization uses Unicode NFKC, lowercases, replaces punctuation with spaces and trims. Empty values, redacted/masked/hidden/withheld and missing-value sentinels, and punctuation-only masks do not provide evidence. These cues do not use a NUH regex, fuzzy matching or fabricated scores. The generic Potential collisions only checkbox includes any customer participating in a derived pair, even if its counterpart is outside another active filter. Edges are shown only when both endpoints are visible. Under redaction, the NUH pair still follows from its shared actual aliases; unrelated records do not match on `[redacted]`.

The selected customer's duplicate candidates, scores and evidence still come from `POST /api/duplicates` with `{name, identifier, email, type:'Customer'}`; the current record is excluded. Scores are heuristic similarity on 0–100, not probabilities. The graph's exact-field review cues and the backend's heuristic candidates have distinct definitions and can differ. Errors and empty results are explicit.

Search matches customer name, identifier, email and aliases. Country, confirmed-product and potential-collision filters intersect. Customer nodes select the inspector; country nodes apply the country filter on a single click; product nodes apply the confirmed-product filter on a single click. Enter/Space on focused nodes performs the same action, while React Flow's keyboard navigation and native customer/filter selectors remain available. The customer selector exposes every record independently of graph filters. Changing the inspector selection alone does not clear the current exploration filters.

The inspector allows any different bootstrap customer as a simulation target. `POST /api/simulate` receives `{sourceId,targetId}`. Returned before/after customer counts and target quantities, source quantity, affected orders, total quantity and explanation are displayed. Quantity output and the table caption explicitly identify all-signal quantities, as distinct from the graph's confirmed-only demand. Conservation is checked explicitly as `before.sourceQuantity + before.targetQuantity === after.targetQuantity`. The page never applies a merge or modifies bootstrap records. Stale evidence and simulation responses are ignored when selection/target changes. API failures are shown inline; bootstrap and evidence support retry.

The canvas uses teal customer nodes, navy product nodes, neutral country nodes, and orange potential collisions. Sidebar stacks below the graph on narrow screens. Inputs have accessible labels, native controls and visible focus; graph nodes have visible keyboard focus; updates use live regions and reduced-motion preference is respected.

Owned files: `src/components/Intelligence.tsx`, `src/components/Intelligence.css`, and this note. No backend or shared component changes.
